# Object melee A/B diagnostic experiments

These are manual-melee diagnostic modes, NOT native attack dispatch implementations. Use Mods > DEV > Melee Tests. Select A, B or C using its own ON/OFF button. Enabling a test automatically enables discovery and the grab laser for the session; turning it off restores the user's original settings. Selecting another test disables the previous one. With the weapon in the right hand, aim the left hand at an untouched grey barrel, hold left Grip, then manually trigger a normal melee (physical punch or normal melee input if enabled). Do not release until the result is visible. Test A and B on separate untouched props, at near and far range; also test a miss and an obstructed prop. Save the normal runtime log and note which objects were hit. Look for [MELEE-PROBE], [MELEE-A], and [MELEE-B].

A logs the offhand aim, head direction comparison, reach and ray-origin proxy candidate. B logs preselected stable native entity/model and vtable RVAs; both correlate manually requested native melee input with same-entity native displacement before normal grab acquisition. Selection is not a collision trace, line of sight, or independent melee contact proof. No extra damage, attack, force, input routing, native memory write or automatic melee is added. A/B are mutually exclusive with C and OFF at startup. Native attack-origin/direction and direct impact ABI must still be independently identified and validated before automatic triggering. Keep ordinary object discovery, calibration and native input unchanged.

## C — ordinary native melee before grab
C is an actual input-level experiment. Enable C under Melee Tests, use right-hand weapon / physical left Grip, face and aim at a fresh grey prop at close native melee distance in an empty test area. Press and hold left Grip once without manually punching. A world-thread proxy selection queues one ordinary 200 ms JOY8 pulse, then the normal grab path may acquire only that same native entity if movement is observed. Already moving targets bypass the wake pulse. No automatic retry while held; release Grip to rearm. No extra force, fake collision, damage/animation edits or new native attack ABI. Following the user's build 113 test, C explicitly uses a fixed 2m eligibility/laser reach regardless of the ordinary grab slider. A temporary left AIM controller pose override feeds the existing native 6DOF source 60ms before JOY8, for 200ms of input and up to 300ms of post-input contact time. It does not switch weapon ownership, input bindings or calibration. The native weapon model may temporarily move; actual melee direction and line of sight must still be verified in headset. Menu, tracking loss, Grip release, gun input or generation change cancel the override. The prior C implementation remains in commit 43257d7; build 113 is the known working baseline. Logs [MELEE-C] report queue, pulse, cancellation, timeout, and native hold confirmation. A/B remain manual probes. Runtime validation pending.
