# Pistol Grapple experiment
Original Grapple Grab remains its own toggle and its original melee override is retained. New Pistol Grapple toggle is mutually exclusive with the original, session-only; enabling it saves original Grapple Grab OFF. Original melee preference is retained but the new variant automatically enables its own melee activation. Both share fixed 2m targeting, geometry investigator, attachment, and native release. Already-moving props bypass weapon switching.
Stationary candidate requests the proven native pistol hotkey. Wait for actual current weapon acknowledgement (950ms maximum), then use left-hand weapon pose submission and a 60ms lead / 200ms JOY8 hold / 300ms contact tail. Render-only scale suppression applies to pistol and expires automatically. The actual input assignments stay right-weapon/left-grip while the weapon pose update temporarily uses left-hand mode. On native attachment, release, conflicting input, timeout, or menu interruption restore the original weapon using its existing native hotkey; restoration is deferred until gameplay returns and acknowledged, with one retry on timeout. Generation change discards stale requests. Direct number-row weapons 1–8 only in this first experiment: unsupported original weapons reject the activation rather than risk losing them. Native damage, sound and animation unchanged. No new native engine functions. The left-directed melee and pistol hide remain unverified in headset; compile/runtime validation pending. Restore failure is logged and may require manual weapon selection. Current grapple anchor is still estimated, not actual render mesh.
